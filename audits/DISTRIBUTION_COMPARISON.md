# Comparing generated molecular distributions

Run from the repository root:

```bash
python compare_distributions.py --reference-dataset qm9
sbatch cluster/experiments/compare_distributions.slurm --reference-dataset qm9
```

With no split specified, **train, validation and test are evaluated separately**.
Both D4 and MiDi are processed by default. Each compares Base, MMFF and Atom
details using the same saved generation files across reference splits. No model
is trained and no molecules or dataset caches are generated by this workflow.

Select a single model/split or change the dataset:

```bash
python compare_distributions.py --model midi --reference-split validation
python compare_distributions.py --reference-dataset gdb13 --model d4
python compare_distributions.py --reference-dataset zinc250k --reference-splits train test
```

`valid` and `val` are aliases for `validation`. The validation directory in the
dataset cache remains `valid`; only its output folder is named `validation`.
An explicit `--reference-split full` remains available. Dataset caches and saved
generations must already exist. Missing references are reported as failures;
another split is never substituted, and remaining splits continue.

## Output structure

```text
outputs/distribution_comparison/
  qm9/
    d4/
      train/
        REPORT.md
        images/           # up to three figures used by the report
        details/
          analysis/       # descriptor counts and source-generation provenance
          distributions/  # all descriptor figures, CSV and joint JSON
          scores/         # numerical metrics, CSV, complete plots and intermediate summary
          statistics/     # permutation tests, CSV, JSON and intermediate summary
      validation/         # same structure, a separate report
      test/               # same structure, a separate report
    midi/                 # same structure
  gdb13/                  # independent dataset outputs
```

The single public `REPORT.md` combines sample counts, generation validity,
uniqueness, MMFF coverage, main figures, distribution-distance rankings,
Wasserstein results, weighting sensitivity and seed-level statistical tests.
Local links point into `details/`; there is no need to open intermediate reports.
Other images, PDFs, CSV and JSON are kept below `details/`, not beside REPORT.md.

Rerunning a scope refreshes its report. If a step fails, REPORT.md records that
failure instead of presenting an earlier report as the current result. Existing
historical `qm9_test_job...` output directories are left untouched.

Tests and Holm corrections are computed separately within each reference split.
This workflow does not test train against validation/test, or D4 against MiDi.
The three reference splits differ in sample size and must not be treated as
identically calibrated distance samples.

## Additional controls

`--output-root PATH` changes the root while preserving dataset/model/split
subdirectories. `--output-dir` is an alias. `--expected-seeds`, `--max-reference`,
`--max-generated`, `--seed`, `--top-k`, `--group-weights`, `--alpha` and
`--max-permutations` control the existing analysis and scoring settings.
`--generated NAME=PATH` selects explicit inputs and requires one `--model`.
`--checkpoints-root` and `--reference-root` override input locations.

`compare_three_representations.py` without `--report` also starts this unified
workflow. With `--report PATH`, it remains a detailed plotter for a saved
analysis. `compare_generated_distributions.py` without a split starts all three
references for its selected model; explicit `--reference-split` and `--output`
retain the technical single-split analyzer used internally.
